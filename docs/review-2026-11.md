## 1. Replacing coot with gemmi – done (#14)

### a) Double-difference map + peak search – done

Implemented in `calc_map.py`:

- `anode.pha` is read with `read_pha` (format confirmed on real data: h k l F FOM φ σ, FOM = 1.0)
  and converted to a map with `pha_to_map`. The "below" map uses the same grid as "above".
- Peaks are found with `gemmi.find_blobs_by_flood_fill` above `threshold × map rms`
  (`np.std` of the map, which equals the rms gemmi writes into the CCP4 header).
- Peak positions are blob centroids (much closer to the true site than the grid maximum),
  moved to the symmetry copy nearest the model, with symmetry duplicates removed.
- Checked against the coot version on real data.

Not done from the original suggestions:

- **Simpler data flow:** peaks are still written to `found_peaks.dat` and regex-parsed back in
  `viewer.parse_peaks`, rather than passed as `list[PeakData]`.
- **gemmi version in dlstbx:** `find_blobs_by_flood_fill` and `Blob.centroid` were tested with
  gemmi 0.7.5. Check if the dlstbx gemmi version changes.

### b) Renders – done

`render_diff_map_peaks`, `view_as_quat` and `find_protein_centre` were removed, along with the
coot, raster3d `render` and `find-blobs` dependencies. `peak_N.png` is no longer produced.
`generate_coot_viewer_script` is kept (it only writes `coot_view.py`).

## 3. Robustness and structure – not started

Several of these would be superseded by the workflow in section 4 (which removes cad, scaleit,
mtzutils, truncate and the two dimple runs), so it may be better to do that first.

- **Check return codes:** `ccp4_command` and `run_dimple` never check `returncode`. A dimple
  failure surfaces later as a confusing `are_pdbs_similar` error. (The coot calls are gone.)
- **Avoid `shell=True` with f-string paths:** paths with spaces break. Use list arguments and
  pass keyword scripts with `input=` instead of heredocs.
- **Make it a proper package:** a `main()` function plus a `pyproject.toml` with a console
  entry point, instead of module-level code and `sys.path`-dependent imports.
- **Add tests:** the map and peak code is now pure gemmi, so it can be tested without CCP4
  (a synthetic map with a known site was used during development). Add a small regression
  dataset with expected peak positions.
- **Read the map once:** `save_cropped_maps` re-reads the full map and the PDB 2× per peak.
- **Fix the units label:** `found_peaks.dat` reports "Electron Density = … e/Å^3", but the
  ANODE maps are σ-normalised (rms ≈ 1), so this value is really σ. Report σ, or absolute
  values once the maps are on an absolute scale (section 4).
- **Drop the R-free flags bug:** cad in `scaling.py` takes columns from
  `crystals()[1].datasets()[0]`, so `FreeR_flag` (in the base dataset) is dropped. Moot if the
  scaling step is removed.
- **Tidy up:** delete or gitignore `src/metal_id/test.py` and `.vscode/`. `file_or_code` in

## 4. Anomalous map workflow (new, 2026-11-20)

Findings from a full metal_id run on thermolysin (2TLX), data at 3.024 Å (above the Ca K edge)
and 3.179 Å (below). Run outputs and test scripts are in the git-ignored `local_data/`.

### The current scaling step has no effect

- scaleit scales only `F`/`SIGF` (by 1.1464 here). Its log claims the same scale is applied
  automatically to IMEAN, I(+) and I(-), but comparing the files shows they are unchanged
  (ratio exactly 1.0000 for every reflection).
- dimple's ANODE branch: pointless → `reindexed.mtz` → cad → `prepared.mtz` → mtz2sca (reads
  I(+)/I(-)) → SHELXC → ANODE. `prepared.mtz` is made before refinement and only read by
  refmac, so refmac's model-based scale never reaches ANODE. Refmac's output (`final.mtz`)
  has no anomalous columns anyway: refmac writes only its `LABIN` columns (`F`, `SIGF`,
  `FreeR_flag`) plus calculated ones.
- SHELXC/ANODE normalise the data: both ANODE maps have rms ≈ 0.9 (σ units). So the current
  double difference is effectively "σ-normalised above − σ-normalised below", whatever the
  input scale.

### σ-normalised maps don't cancel properly

S and Zn should nearly cancel in the double difference (tabulated f″ rises only ~9% from above
to below), but in σ units they are 30–50% larger in the below map, because the strong Ca signal
inflates the above map's rms. The two refmac maps' rms differ by ~20% (0.024 vs 0.020).

### Refmac anomalous maps

Test: ctruncate (I(+)/I(-) → F(+)/F(-)), then refmac with
`LABIN FP=F SIGFP=SIGF F+=F(+) SIGF+=SIGF(+) F-=F(-) SIGF-=SIGF(-)`,
`ANOMALOUS WAVELENGTH <λ>`, `NCYC 0`, using one refined model (`dimple_above/final.pdb`) for
both datasets. (Passing I(+)/I(-) directly failed with a column type error.)

- Refmac sets f′/f″ from the wavelength (matching gemmi's `cromer_liberman` values) and writes
  `FAN`/`PHAN` (anomalous map) and `DELFAN`/`PHDELAN` (anomalous difference against the model).
- R = 0.195 (above), 0.194 (below, model not refined against it; 0.178 with its own model).
- Maps correlate 0.85–0.86 with ANODE's. The double difference finds the same three Ca peaks,
  slightly stronger (24.4/24.1/22.1σ vs 23.2/21.9/21.0σ).
- Map values are on a common, model-based (≈ absolute) scale. Below/above ratios: Met205 1.00,
  Met120 0.98, Zn 1.20 (expected 1.09); Ca 0.04/0.13/0.01 (expected 0.12). Residuals at S/Zn in
  the double difference: −0.1 to −1.1σ, against −0.5 to −2.2σ for the ANODE-based map.
- One model for both datasets works as well as each dataset's own dimple model.
- Building the difference from common reflections to the lower resolution limit (17,287
  reflections to 2.08 Å) changes little here, but should be the default.
- `DELFAN` flagged Ca324: modelled as Ca but no anomalous signal (−5.4σ in the above map; it
  is also ~1.5σ in FAN above and negative below). Met205 SD is −6.5σ in `DELFAN` below; not
  explained yet.

Caveat: one dataset with a strong signal. Test on a weaker case (partial occupancy, different
element) before relying on it.

### When dimple runs molecular replacement

Tested by rerunning metal_id with the CRYST1 record removed from 2TLX
(`local_data/metal_id_no_cell/`), which makes dimple skip reindexing and rigid-body refinement and
go straight to Phaser. From dimple's source (v2.7), after Phaser the data come from
`phaser.1.mtz`: `prepared.mtz` is built from it, and that is what mtz2sca reads for ANODE.

- **The anomalous columns survive Phaser.** `phaser.1.mtz` contained all the original columns
  (IMEAN, I(+)/I(-), F, SIGF) plus Phaser's own (FC, PHIC, FWT, …, FOM). mtz2sca read I(+)/I(-)
  and SHELXC read the same 36,636 reflections as in the normal run. (Whether Phaser changes the
  values couldn't be checked, as dimple deletes `phaser.1.mtz` and `prepared.mtz`; it wouldn't
  matter for ANODE, which normalises the data.)
- **The space-group mismatch is harmless.** Phaser changed the space group from P622 (data
  header) to P6₁22. SHELXC is still given the pre-MR space group (P622), but ANODE takes the
  space group from the model ("Space group: P 61 2 2"). Both have the same point group, so
  SHELXC's handling of Friedel pairs is unaffected.
- **Same result.** Peaks at 23.11/21.59/20.21σ on the same three Ca sites (normal run:
  23.24/21.87/20.99σ). Refinement ends worse: R/Rfree 0.228/0.250 above and 0.222/0.260 below,
  against 0.193/0.235 and 0.176/0.224.
- **Coordinates are in a different frame.** Phaser placed the model at an equivalent but
  different origin: the MR model matches the normal-run model after (−x, −y, z+½) and an origin
  shift of (0, 0, ½), 0.16 Å rms over Cα. So peak coordinates after MR (e.g. Ca325 at
  (31.56, 34.55, 15.89) instead of (14.77, 45.59, 15.72)) don't match the user's model or a
  deposited structure, even though the sites are the same.

Conclusion: MR doesn't corrupt the anomalous data, but it moves the results into a different
frame and gives a less well refined model. Requiring an already refined model (below) avoids
both; if the model doesn't fit the data, metal_id should stop and ask the user to run dimple or
MR first.

### Proposed workflow

Input: data above and below the edge, plus a model already refined against one of them.

For each dataset:

1. pointless against the model (consistent indexing).
2. ctruncate to get F(+)/F(-).
3. refmac with the anomalous columns and the wavelength (0 to a few cycles); fail with a clear
   message if R is too high.
4. Build the anomalous maps in gemmi from `FAN`/`PHAN`, using common reflections to the common
   resolution.

Then the double difference and peak search as now, the Mol* viewer, and optionally `DELFAN`
peaks near metal sites as a check of the model's metal assignments.

This replaces cad/scaleit/mtzutils/truncate, both dimple runs, `are_pdbs_similar` and ANODE.
It also never runs MR, so results stay in the frame of the user's model. If the R check fails,
stop with a message telling the user to refine the model first (e.g. with dimple).
For sites near the absorption edge, consider giving measured f′/f″ (e.g. from a fluorescence
scan) instead of tabulated values, since tabulated values are least reliable close to an edge.
